📚 ما هي الوراثة؟

الوراثة هي مفهوم يسمح للكلاس بأن يكتسب الخصائص والدوال من كلاس آخر موجود مسبقاً، بدلاً من كتابة الكود من الصفر.

💡
الفائدة الكبرى: توفير الوقت وإعادة استخدام كود مجرّب وخالٍ من الأخطاء، مما يرفع جودة البرنامج وكفاءته.

عند إنشاء كلاس جديد، بدل التصريح بأعضاء جديدة بالكامل، يمكنك جعل الكلاس الجديد يرث الأعضاء من كلاس موجود.

🏷️ المصطلحات الأساسية

المصطلحالمعنىفي لغة C++
Superclassالكلاس الأب (الرئيسي/العام)Base class
Subclassالكلاس الابن (الفرعي/المتخصص)Derived class
📌
قواعد ذهبية:
  • كل subclass ممكن يصير superclass لكلاسات أخرى لاحقاً.
  • الكلاس الابن أكثر تخصصاً من الأب (يضيف خصائصه ودواله الخاصة).
  • في جافا: كل كلاس له أب مباشر واحد فقط لا غير.

🔗 أنواع الوراثة

مباشرة وغير مباشرة

• الأب المباشر (Direct): الكلاس الذي ترث منه صراحةً باستخدام extends.

• الأب غير المباشر (Indirect): أي كلاس أعلى في السلسلة الهرمية.

🌳
كل كلاس تكتبه في جافا يرث تلقائياً (implicitly) من الكلاس java.lang.Object — حتى لو لم تكتب extends.

مفردة ومتعددة

النوعالوصفهل تدعمها جافا؟
Single Inheritanceالوراثة من أب مباشر واحد✅ نعم
Multiple Inheritanceالوراثة من أكثر من أب مباشر❌ لا (بعكس C++)

🌟 فوائد الوراثة

① تقليل تكرار الكود (Less Redundancy): الخصائص المشتركة بين كل الأبناء تُكتب مرة واحدة في الأب.

② سهولة التعديل (Ease of Modification): لإضافة خاصية مثل facebookId، تضيفها في الأب فقط ويرثها الجميع.

③ القابلية للتوسع (Extensibility): دالة تعمل مع الكلاس الأب تعمل مع كل الأبناء، حتى لو أُنشئوا لاحقاً.

🎯
مثال: دالة sendInvitation(Employee e) تقبل أي كلاس يرث من Employee (مثل Manager أو Programmer)، حتى لو عرّفته بعد كتابة الدالة. هذا ما يجعل الكود قابلاً للتوسع.

🔑 الكلمة المفتاحية extends

تُستخدم كلمة extends للدلالة على الوراثة:

Javaclass Car extends Vehicle { ... }   // Car ابن، Vehicle أب

class Circle extends Shape { ... }   // Circle ابن، Shape أب

🟦 مثال: Shape و Rectangle

Object
جذر كل الكلاسات
extends (implicit)↓
Shape (Superclass)
color, name
setColor() · setName()
getColor() · getName() · toString()
extends↓
Rectangle (Subclass)
color, name (موروثة) + length, width
كل دوال الأب + area() + toString()
⚠️
الابن (Rectangle) يصل لكل ما هو public و protected في الأب. لكن الأب (Shape) لا يصل لأي شيء في الابن.

إحصاء: الابن Rectangle عنده 4 خصائص (color, name, length, width) و 7 دوال (5 موروثة + area + toString).

🏗️ الوراثة والبناة (Constructors)

خطوات الـ compiler عند إنشاء كائن:

① إنشاء كائن من الأب ← ينفّذ باني الأب فقط.

② إنشاء كائن من الابن ← يستدعي تلقائياً باني الأب بدون باراميترات (no-arg) أولاً، ثم باني الابن.

③ إذا الأب ما عنده باني بدون باراميترات ← الابن لازم يستدعي باني الأب صراحةً عبر super.

🐞
عند إضافة باني بباراميترات للأب، يختفي الباني الافتراضي، فتظهر أخطاء في كل بناة الابن: cannot find constructor Shape(). الحل: استخدام super.

🔧 الكلمة المفتاحية super

تشير إلى الكلاس الأب، وتُستخدم بثلاث طرق:

① استدعاء متغيرات الأب  ② استدعاء دوال الأب  ③ استدعاء بناة الأب

📍
super() أو super(parameters) يجب أن تكون أول جملة في باني الابن.

مثال على استدعاء دالة الأب (override لـ toString)

Javapublic String toString() {
    return super.toString() + " length=" + length + " width=" + width;
}

super.toString() ينفّذ دالة الأب، وتُضاف النتيجة لباقي السلسلة.

❓
هل تُورّث البناة؟ لا! البناة لا تُورّث، بل تُستدعى صراحةً عبر super أو تلقائياً (الباني بدون باراميترات).

⛓️ تسلسل البناة (Constructor Chaining)

Javaclass Point {
    Point() { System.out.print("Point Constructor ==> "); }
}
class Circle extends Point {
    public Circle() { System.out.print("Circle Constructor ==> "); }
}
class Cylinder extends Circle {
    public Cylinder() { System.out.print("Cylinder Constructor."); }
}
class Project {
    public static void main(String[] args) {
        Cylinder ob = new Cylinder();
    }
}
OutputPoint Constructor ==> Circle Constructor ==> Cylinder Constructor.
📈
لماذا هذا الترتيب؟ إنشاء Cylinder يستدعي باني Circle، الذي يستدعي باني Point أولاً. فالتنفيذ يبدأ من أقدم أب نحو أحدث ابن.

🛡️ معامل الوصول protected

العنصر protected يمكن الوصول له من: أي كلاس في نفس الـ package، أو من الأبناء (حتى لو في package مختلف).

المعاملنفس الكلاسنفس الـ packageالأبناء (package آخر)الجميع

الترتيب من الأضعف للأقوى وصولاً: private → default → protected → public

🌳 كلاس Object ودواله

كل كلاس في جافا ينحدر من java.lang.Object، وهو جذر شجرة الوراثة.

Javapublic class Circle { ... }
// يكافئ تماماً:
public class Circle extends Object { ... }

📝 دالة toString()

ترجع تمثيلاً نصياً للكائن. السلوك الافتراضي يطبع اسم_الكلاس@رقم_hex مثل Loan@15037e5 (غير مفيد) — لذلك يُنصح بعمل override.

⚖️ دالة equals()

تقارن محتوى كائنين. التطبيق الافتراضي يقارن المراجع فقط:

Java// التطبيق الافتراضي في كلاس Object
public boolean equals(Object obj) {
    return this == obj;
}

// مثال على override في Rectangle
public boolean equals(Rectangle obj) {
    return (this.width == obj.width) && (this.length == obj.length);
}
🔍
الفرق بين == و equals:
• == يقارن القيم الأولية أو يفحص إن كان الكائنان لهما نفس المرجع (نفس العنوان).
• equals يفحص إن كان لهما نفس المحتوى (عند عمل override).
• == أقوى لأنه يفحص نفس الكائن بالضبط.

📝 التمرين العملي

صمّم تسلسل كلاسات لنمذجة أنواع المستندات:

① الكلاس الأب: Document

  • protected String authorName
  • private int numberOfPages و private String classificationNo
  • باني بباراميترات + getters/setters
  • الشرط: classificationNo يبدأ بـ H أو S + 4 أرقام (مثل "H1345")، وإلا رسالة خطأ
  • دالة display() تطبع التفاصيل

② الكلاس الابن: Book

  • private String subject و private int yearOfPublishing
  • باني بباراميترات
  • override لدالة display()
  • دالة checkYear() ترجع true إذا نُشر بعد/نفس سنة معينة
  • override لدالة equals() تقارن حسب subject

③ كلاس الاختبار (main)

  • أنشئ كتابين، نادِ display() لهما
  • قارنهما بـ equals واطبع "Equal" أو "Not Equal"
  • نادِ checkYear(2019) للاثنين واطبع النتيجة
💪
جرّب حل التمرين بنفسك أولاً! وإذا احتجت الحل الكامل بكود جافا، اطلبه وسأكتبه لك خطوة بخطوة.
